# qparser

Собирает вопросы с онлайн-тестов и превращает их в `INSERT`-ы для таблиц `questions` /
`answer_options`. Модуль отдельный от `backend`, чтобы зависимости парсера (jsoup, jackson)
не попадали в продовый артефакт.

## Как это работает

Два шага, разделённые намеренно:

```
конфиг.yaml → harvest → questions.json → (глазами) → sql → insert.sql
```

`harvest` ходит на сайт и пишет JSON в каноническом виде, не зависящем от источника.
`sql` знает схему БД и превращает проверенный JSON в запросы. Новый сайт трогает только
адаптер — генератор SQL переиспользуется как есть.

Промежуточный JSON нужен потому, что авторы тестов делают опечатки, вставляют картинки и
пишут комментарии в HTML. Правится один файл, а не сгенерированный SQL.

## Запуск

```bash
mvn package

java -jar target/qparser.jar harvest --config configs/onlinetestpad-1030796.yaml --dry-run
java -jar target/qparser.jar harvest --config configs/onlinetestpad-1030796.yaml
java -jar target/qparser.jar sql --in configs/onlinetestpad-1030796.json --out /tmp/insert.sql
```

- `--dry-run` — берёт три вопроса, печатает разбор и ничего не пишет. С этого стоит начинать
  каждый новый тест: видно, правильно ли определился тип и не поехала ли разметка.
- `--fresh` — не дописывать к существующему JSON, а собрать заново.

## Конфиг

```yaml
url: https://onlinetestpad.com/ru/test/1030796-...
adapter: onlinetestpad
limit: 100          # сколько вопросов взять; убрать — пройти тест целиком
subjectId: 1        # вопрос в практику…
# lessonId: 42      # …либо вопрос урока. Ровно одно из двух.
startOrder: 1       # используется только для вопросов урока
prefill:            # поля, которые тест просит до старта, по атрибуту name
  fio: Иван
dedupeByTitle: true # выключить, если тест повторяет один текст вопроса с разными вариантами
delayMs: 400        # пауза между запросами
out: onlinetestpad-1030796.json   # путь относительно папки конфига
```

`lessonId` и `subjectId` взаимоисключающие — этого требует constraint `questions_owner_check`
в базе. У вопросов практики `order` пишется как `NULL`.

## Повторные запуски

Порядок вопросов на onlinetestpad случайный в каждой сессии, поэтому `limit: 100` из теста на
164 вопроса даёт случайные 100, а не первые сто по порядку автора. У каждого вопроса при этом
есть стабильный серверный id, и harvest его сохраняет — так что повторный запуск дописывает в
тот же JSON только новые вопросы. Дошли до конца теста — просто не запускайте снова.

## Адаптер onlinetestpad

Тест — одна HTML-форма, которая постится сама в себя; следующий вопрос приходит в ответе на
POST. JavaScript не нужен. Адаптер отправляет заведомо неверный ответ, чтобы сайт показал
правильный.

Правильные ответы сайт отдаёт двумя способами, на выбор автора теста: сразу после ответа на
той же странице либо только на итоговой странице разбора. Адаптер читает то, что есть, а
недостающее добирает с итоговой страницы, поэтому конфигурировать режим не нужно.

Типы определяются по разметке:

| Разметка на странице | `question_type` |
|---|---|
| одно текстовое поле | `INPUT` |
| radio | `SINGLE_ANSWER` |
| checkbox | `MULTI_ANSWER` |
| соответствия, порядок, несколько полей ввода | пропускается с предупреждением |

Отдельный случай — интерактивный диктант: вопрос там не текст со списком вариантов, а слово с
пропуском, и варианты живут внутри пропуска. Такой вопрос собирается как `SINGLE_ANSWER`, а
пропуск в тексте записывается многоточием: `пред...дущий`. Диктант с двумя пропусками
пропускается — в `questions` один правильный ответ, а не два.

Пропущенный вопрос всё равно получает ответ наугад: без ответа тест не пускает дальше, и
вместе с одним неподходящим вопросом потерялись бы все следующие за ним.

Пропуски видны в выводе — если их много, тест стоит заменить на другой, а не чинить парсер.
Вопросы с картинками собираются, но с предупреждением: в схеме негде хранить картинку, и без
неё текст вопроса может потерять смысл.

## Адаптер saharina

Тест Захарьиной устроен проще: все вопросы отрисованы на одной странице, одна отправка формы —
и в ответ приходит страница самопроверки с вердиктами. Адаптер отвечает везде первым вариантом;
сайт называет верный ответ для всех вопросов, кроме тех, где первый вариант и был правильным, —
а их видно по вердикту «Верно».

Своих идентификаторов у вопросов сайт не даёт, поэтому `sourceId` собирается из имени теста и
поля формы: `test91.xml#3`. Страница самопроверки не повторяет идентификаторов вообще, вопросы
на двух страницах сопоставляются по позиции — и адаптер сверяет тексты, чтобы заметить, если
это перестанет работать.

Сайт публикует только вопросы с одиночным выбором; всё остальное пропускается с предупреждением.
