# Style guide

Правила визуального оформления мини-аппа подготовки к ЦТ/ЦЭ.
Это не описание готовых компонентов — это набор ограничений, внутри которых
любой новый экран получится согласованным с остальными.

Реализация правил: `src/styles/tokens.css` (значения) и `src/styles/index.css`
(маппинг в Tailwind-утилиты, baseline, кастомные утилиты).

---

## 0. Контекст и принципы

Приложение живёт внутри Telegram, на телефоне, и им пользуются школьники
16–18 лет, которые готовятся к экзамену. Отсюда всё остальное:

1. **Mobile-first и только.** Базовый макет — телефон шириной 360–430px.
   Десктоп — это тот же макет, центрированный в колонке `max-w-app` (480px).
   Брейкпоинты (`sm:`, `md:`) почти не нужны; если понадобился — скорее всего
   компонент спроектирован неправильно.
2. **Содержание важнее оформления.** Главный объект на экране — текст вопроса и
   варианты ответа. Всё остальное (карточки, иконки, тени) не должно спорить с
   ними за внимание.
3. **Спокойно, но не скучно.** Никакого «геймдева»: без градиентов, неона,
   сильных теней и разноцветных иллюстраций. Эмоция появляется только в трёх
   местах — правильный ответ, неправильный ответ и стрик.
4. **Обратная связь мгновенная.** Любое нажатие даёт визуальный отклик за
   ≤150 мс. Ответ на вопрос сразу окрашивается в success/danger и показывает
   пояснение.
5. **Одна и та же вёрстка работает в обеих темах.** Экран пишется один раз,
   через семантические токены; `dark:` в разметке — исключение, а не норма.

## 1. Цвет

### 1.1 Откуда берётся палитра

Палитра — **своя**, не наследуется из темы Telegram.

Почему не `--tg-theme-*`: у Telegram нет понятий «правильный ответ»,
«заблокированный урок», «стрик», «прогресс», а у пользователей бывают кастомные
темы с произвольными (в том числе кислотными) цветами кнопок — контраст в них
не гарантирован. Поэтому от клиента берётся **только режим** (светлый/тёмный),
а конкретные цвета наши.

Режим определяется так:

- внутри Telegram — `WebApp.colorScheme`, с подпиской на событие `themeChanged`;
- в обычной вкладке браузера — `prefers-color-scheme`.

Результат пишется в атрибут `data-theme` на `<html>`: сначала инлайн-скриптом в
`index.html` (до первой отрисовки, чтобы не было вспышки светлой темы), дальше
поддерживается модулем `@/shared/lib/theme`. Ручного переключателя темы в
интерфейсе нет — внутри Telegram он выглядел бы чужеродно.

### 1.2 Токены

Все цвета — семантические: токен называется по роли, а не по оттенку.
Каждый доступен как утилита (`bg-surface`, `text-muted`, `border-border`).

**Поверхности**

| Токен            | Роль                                                          |
| ---------------- | ------------------------------------------------------------- |
| `bg`             | фон страницы                                                  |
| `surface`        | карточка, плашка урока, вариант ответа                        |
| `surface-raised` | то, что «плавает»: нижняя навигация, модалка, sticky-хедер     |
| `surface-sunken` | утопленное: инпут, трек прогресс-бара, код, скелетон          |
| `border`         | волосяная граница по умолчанию                                |
| `border-strong`  | заметная граница: контур инпута, разделитель с акцентом       |
| `overlay`        | затемнение под модалкой                                       |

**Текст** — ровно три уровня, четвёртый не заводим:

| Токен    | Роль                                                        |
| -------- | ----------------------------------------------------------- |
| `fg`     | основной текст: вопрос, заголовок, ответ                    |
| `muted`  | вторичный: подписи, метаданные, описание урока              |
| `subtle` | приглушённый: плейсхолдер, disabled, заблокированный урок   |

**Смысловые группы.** У каждой — четыре токена по одной схеме:

- `X` — заливка/иконка/акцентная линия,
- `X-fg` — текст поверх заливки `X`,
- `X-soft` — бледная подложка (бейдж, подсветка выбранного ответа),
- `X-soft-fg` — текст поверх `X-soft`.

| Группа    | Когда                                                                     |
| --------- | ------------------------------------------------------------------------- |
| `primary` | действия, выбор, прогресс, фокус, активная вкладка                        |
| `success` | правильный ответ, пройденный урок, активная подписка                      |
| `danger`  | неправильный ответ, ошибка запроса, деструктивное действие                |
| `warning` | подписка заканчивается, некритичное предупреждение                        |
| `streak`  | только стрик в практике (`streak`, `streak-soft`, `streak-soft-fg`)       |

Плюс `link` — для ссылок внутри текста.

### 1.3 Правила

- **Хардкодить цвет нельзя.** Ни `bg-blue-500`, ни `#4F46E5`, ни `bg-white`,
  ни `text-black` — палитра Tailwind по умолчанию в тёмной теме не переключается.
  Если нужного оттенка нет — добавь токен в `tokens.css` (сразу оба значения),
  а не литерал в разметке.
- **Цвет не единственный носитель смысла.** Правильный/неправильный ответ всегда
  сопровождается иконкой (`Check` / `X`), заблокированный урок — замком.
- **Не более одного акцента в блоке.** На карточке урока либо `primary`-кнопка,
  либо `success`-бейдж — не оба сразу.
- **`primary` — для одного главного действия на экране.** Второстепенные кнопки
  делаются на `surface` с `border`.
- Контраст: текст — минимум 4.5:1, крупный текст (≥24px) и иконки — 3:1.
  Пары токенов подобраны так, что это выполняется в обеих темах; произвольные
  комбинации (например `text-subtle` на `bg-primary`) проверяй сам.

## 2. Типографика

Шрифт — системный (`font-sans`): нативно выглядит в Telegram на iOS и Android
и ничего не грузится по сети. Шрифты не подключаем.

| Утилита     | Размер/интерлиньяж | Где                                        |
| ----------- | ------------------ | ------------------------------------------ |
| `text-xs`   | 12 / 1.33          | бейджи, «Урок 3 из 12», даты               |
| `text-sm`   | 14 / 1.43          | вторичный текст, подписи, пояснения к цифрам |
| `text-base` | 16 / 1.5           | body по умолчанию, варианты ответа          |
| `text-lg`   | 18 / 1.5           | текст вопроса, заголовок карточки           |
| `text-xl`   | 20 / 1.4           | заголовок экрана                            |
| `text-2xl`  | 24 / 1.25          | числа в статистике                          |
| `text-3xl`  | 32 / 1.15          | прогнозируемый балл, счётчик стрика         |

Правила:

- **Минимум для читаемого текста — 14px.** 12px только для служебных подписей.
  На инпутах — не меньше 16px, иначе iOS зумит страницу при фокусе.
- **Начертания: 400 / 500 / 600.** 400 — текст, 500 — подписи и лейблы,
  600 — заголовки и кнопки. 700 — только для `text-3xl` (балл, стрик).
  `italic` не используем, ALL CAPS — тоже.
- **Иерархия делается размером и цветом, не жирностью.**
- Заголовок экрана на странице ровно один (`h1`, `text-xl font-semibold`).
- Цифры в статистике — `tabular-nums`, чтобы не «прыгали» при обновлении.
- Длинные слова в вопросах: `break-words` на контейнере текста вопроса.
- Текст интерфейса — русский, без сокращений и без обращения на «ты» через раз:
  везде нейтрально-вежливое «Продолжить», «Проверить», «Следующий вопрос».

## 3. Размеры, отступы, форма

**Сетка — 4px** (шаг Tailwind по умолчанию). Значения вне шкалы (`p-[13px]`)
не используем.

| Что                                  | Значение                        |
| ------------------------------------ | ------------------------------- |
| Боковые поля экрана                  | `px-gutter` (16px + safe-area)  |
| Между карточками в списке            | `gap-2` / `gap-3`               |
| Между смысловыми блоками экрана      | `gap-6`                         |
| Внутренние поля карточки             | `p-4`                           |
| Внутренние поля кнопки               | `px-4 py-3`                     |
| Высота нижней навигации              | `h-nav` (64px) + safe-area      |
| Ширина контентной колонки            | `max-w-app` (480px), `mx-auto`  |

**Скругления — семантические, выбираются по роли, а не по размеру:**

- `rounded-control` (12px) — кнопки, инпуты, варианты ответа, бейджи-плашки;
- `rounded-card` (16px) — карточки уроков, тайлы статистики;
- `rounded-sheet` (20px) — модалки и bottom sheet (сверху);
- `rounded-full` — аватар, пилюли, круглые иконки-кнопки, прогресс-бар.

**Тени — три штуки, больше не заводим:**

- `shadow-card` — карточка, лежащая на фоне;
- `shadow-nav` — нижняя навигация и sticky-элементы;
- `shadow-pop` — модалка, попап.

В тёмной теме тени почти не видны — там глубина создаётся разницей
`bg` → `surface` → `surface-raised` и границей `border`. Поэтому у карточки
должны быть **и** тень, **и** фон: `bg-surface shadow-card`.

**Тач-таргеты: минимум 44×44px** (`min-h-11`) у всего кликабельного, включая
иконки-кнопки. Между соседними интерактивными элементами — минимум 8px.

## 4. Состояния и интерактивность

Порядок, в котором состояния описываются в классах:
`base → hover → active → focus-visible → disabled`.

- **Hover не работает на телефоне.** Основное состояние нажатия — `active:`
  (`active:bg-primary-hover`, `active:scale-[0.98]`). `hover:` добавляем как
  бонус для десктопа, но никогда не полагаемся на него.
- **Фокус.** Глобальный `:focus-visible` (2px `primary`, отступ 2px) уже задан в
  `index.css`. Убирать `outline` или переопределять его в компонентах нельзя.
- **Disabled** — `opacity-50` + `cursor-not-allowed`, без смены цвета.
- **Loading.** Кнопка не исчезает и не меняет ширину: спиннер заменяет текст
  внутри той же кнопки. Списки грузятся скелетонами на `surface-sunken`
  (`animate-pulse`), а не полноэкранным спиннером — экран не должен «прыгать».
- **Пустое состояние** — иконка `subtle`, заголовок `text-base font-medium`,
  пояснение `text-sm text-muted`, при необходимости одна кнопка действия.
- **Ошибка запроса** — короткий текст + кнопка «Повторить». Технические коды и
  стектрейсы пользователю не показываем.

**Анимация.** Только `opacity`, `transform` и `color`/`background-color`;
`height`/`width` не анимируем. Длительность 120–200 мс (`duration-150`),
easing по умолчанию. Есть `animate-shake` — короткая тряска для неправильного
ответа. Блок `prefers-reduced-motion` в `index.css` гасит анимации глобально;
это значит, что анимация никогда не должна быть единственным способом что-то
сообщить.

## 5. Доступность

- Семантические теги: `button` для действий, `a`/`Link` для переходов.
  `div` с `onClick` — нет.
- Иконка без подписи — `aria-label` на кнопке; декоративная иконка рядом с
  текстом — `aria-hidden`.
- Все иконки из `lucide-react`, размер задаётся классом (`size-4`, `size-5`),
  цвет наследуется от `text-*`.
- Результат ответа объявляется скринридеру: контейнер с пояснением —
  `role="status"` (или `aria-live="polite"`).
- Прогресс урока — `role="progressbar"` с `aria-valuenow`/`aria-valuemax`,
  либо текстом «Вопрос 4 из 10» рядом.
- Заблокированный урок — `disabled` + `aria-disabled`, а не просто серый цвет.

## 6. Паттерны экранов

Общее: у каждого экрана есть заголовок (`h1`), контент идёт вертикальным
стеком (`flex flex-col gap-6`), горизонтального скролла нет никогда.

**Нижняя навигация (4 вкладки: ДЗ / Практика / Статистика / Профиль).**
`fixed bottom-0`, `bg-surface-raised shadow-nav`, `pb-safe`, `h-nav`.
Вкладка = иконка `size-5` + подпись `text-xs`. Активная — `text-primary`,
неактивная — `text-subtle`. Контент страницы отступает `pb-nav-safe`
(уже сделано в `root-layout`).

**ДЗ — список уроков.** Карточка: `bg-surface rounded-card p-4 shadow-card`.
Три состояния:

- _доступен_ — обычная карточка, справа шеврон;
- _пройден_ — иконка `Check` в кружке `bg-success-soft text-success-soft-fg`
  и результат («8 / 10») в `text-sm text-muted`;
- _заблокирован_ — `opacity-60`, текст `subtle`, иконка `Lock`, не кликается.

Уроки сгруппированы по предметам — заголовок группы `text-sm font-medium text-muted`.

**Прохождение теста.** Сверху прогресс: тонкий бар `h-1 rounded-full`,
трек `bg-surface-sunken`, заливка `bg-primary`. Дальше текст вопроса
(`text-lg`), ниже варианты ответа — карточки на всю ширину,
`rounded-control border`, минимум 48px высоты. Состояния варианта:

| Состояние            | Оформление                                                |
| -------------------- | --------------------------------------------------------- |
| обычный              | `bg-surface border-border`                                 |
| выбран (до проверки) | `bg-primary-soft border-primary text-primary-soft-fg`      |
| верный               | `bg-success-soft border-success text-success-soft-fg` + `Check` |
| неверный             | `bg-danger-soft border-danger text-danger-soft-fg` + `X`   |

Пояснение после ответа — блок `bg-surface-sunken rounded-control p-3 text-sm`.
Кнопка «Далее» — sticky снизу, полная ширина, `bg-primary`.
Для типа `input` — поле `bg-surface-sunken rounded-control` с текстом 16px.

**Практика.** Тот же экран вопроса, но без прогресс-бара и без счёта в конце.
Вверху — стрик: иконка `Flame` цветом `streak`, число `text-3xl font-bold`,
подложка `bg-streak-soft`. При обнулении стрика — `animate-shake`, не красный
экран.

**Статистика.** Сверху — прогнозируемый балл: крупная карточка,
число `text-3xl`, подпись `text-sm text-muted` о том, что это оценка ИИ по
данным за последний месяц. Ниже — сетка тайлов `grid grid-cols-2 gap-3`,
в тайле число `text-2xl tabular-nums` и подпись `text-sm text-muted`.
Дальше — диаграммы по правилам §6.1.

**Профиль.** Карточка пользователя (имя, `@username`), ниже список предметов с
подпиской: активная — бейдж `success-soft`, истекает в ближайшую неделю —
`warning-soft`, истекла — `danger-soft`. Дата — `text-sm text-muted`.

### 6.1 Диаграммы

Диаграмма — это цифры, а не украшение: у каждой ровно **одна серия**, поэтому
отдельная «палитра для графиков» не нужна и не заводится. Многосерийные графики
(две линии, стеки) без нового набора токенов не рисуем — сначала обсуждение.

**Цвет по смыслу серии.**

| Что показываем              | Заливка                                     |
| --------------------------- | ------------------------------------------- |
| количество (сколько решено) | `bg-primary`                                |
| качество (точность темы)    | `success` ≥80%, `warning` 50–79%, `danger` <50% |
| трек/пустое значение        | `bg-surface-sunken`                         |

Цвет никогда не единственный носитель смысла: рядом с каждой полосой стоит
процент цифрами (`text-xs tabular-nums`), у столбика — `aria-label` с датой и
значениями. Радуги, градиенты и «чем больше, тем темнее» на неупорядоченных
категориях — нет.

**Метрика.** Столбик/полоса не толще 24px, скругление со стороны данных
`rounded-t-sm` (4px), у основания — квадрат. Трек полосы — `h-1`…`h-1.5`
`rounded-full bg-surface-sunken`. Ось — волосяная `border-t border-border`,
пунктира нет. Подписи по оси — `text-xs text-subtle`, значения не подписываем
у каждой точки.

**Взаимодействие.** Ховера на телефоне нет, поэтому вместо тултипа — тап по
столбику: он подсвечивается `bg-primary-soft`, а его цифры подставляются в
подпись над графиком (`role="status"`). Значение при этом всегда доступно и без
тапа — через `aria-label` столбика.

**Единственный инлайн-стиль в приложении** — длина или высота полосы
(`style={{ width: '72%' }}`), потому что это данные, а не оформление, и утилитой
рантайм-значение не выражается. Всё остальное по-прежнему только классами.
Готовый прогресс-бар — `shared/ui/progress-bar.tsx`, не копипастим.

**Пустое состояние.** Ноль ответов — это не пустой график из нулевых столбиков,
а текст «здесь появится …»: см. §4.

**Админ-панель.** Тот же набор токенов и компонентов, никакого отдельного
оформления: те же карточки, кнопки и формы. Отличие только в плотности —
допустимы `p-3` вместо `p-4` и `text-sm` в списках.

## 7. Как писать стили

- Только Tailwind-утилиты в разметке. Своих CSS-классов и `style={{}}` нет.
- В `index.css` попадает только baseline и то, что утилитами не выражается
  (safe-area, глобальный фокус). Классы компонентов туда не пишем.
- Порядок классов сортирует `prettier-plugin-tailwindcss` — руками не правим.
- Условные варианты (кнопка primary/secondary, состояние ответа) — через
  объект-словарь классов, не через конкатенацию строк в JSX.
- Повторился визуальный блок больше двух раз — выносим в `src/shared/ui`.
- Новый токен добавляется в `tokens.css` **сразу для обеих тем** и мапится в
  `@theme inline` в `index.css`. Одно без другого — сломанная тёмная тема.

### Чек-лист перед коммитом экрана

1. Нет литеральных цветов и произвольных значений (`[...]`) в классах.
2. Экран проверен в обеих темах — переключением `data-theme` на `<html>`
   в devtools.
3. При ширине 360px ничего не обрезано и нет горизонтального скролла.
4. Все кликабельные элементы ≥44px и имеют видимый фокус.
5. Состояния loading / empty / error нарисованы, а не забыты.
